# 断行引擎（Markdown 打印稿排版）

内部有个把 Markdown 转成打印稿的小工具，排版一直用现成的库，中英混排的时候特别难看：标点跑到行首，开括号留在行尾，英文单词从中间被劈开。客户提了两次意见，这次自己写一个断行引擎，只管断行这一件事。

宽度不能按字符个数算，全角和半角不一样宽，宽度表见 samples/widths.txt。英文单词、数字、连字符连起来的词都不能从中间断开，除非它本身比一行还长，那种才强制拆。禁则见 samples/kinsoku.txt：行首不能放什么、行尾不能放什么照表来；标点连着出现的时候要一串一起处理，不能顾头不顾尾。断行不能贪心，不能这一行尽量塞满再看下一行，要按下面的代价函数取全局最优。文本长起来也不能变慢，一本书的量要在几秒内排完，别写成指数级的搜索。同一份输入跑两遍结果必须一模一样，不能有随机，也不能依赖遍历顺序。实现只用标准库，测试用 unittest。

## 宽度规则

宽度单位是半角：半角字符 1 个单位，全角字符 2 个单位。码位到宽度的区间全部写在 samples/widths.txt 里，每行是「起始码位 结束码位 宽度」，表里没有的码位按默认宽度 1 算。

## 禁则

samples/kinsoku.txt 里两行列出了行首禁则字符与行尾禁则字符。约束是硬的：

- 断点后面紧跟的字符不能是行首禁则字符（标点连着出现时，因为串里每个字符都在表里，整串会自然一起被推到下一行）；
- 断点前面紧挨的字符不能是行尾禁则字符。

## 断点候选

文本先切成单元：英文单词、数字、连字符连起来的词（例如 `state-of-the-art`）各算一个单元；每个中文字符、假名、全角标点各算一个单元；空格是分隔符，不单独成单元。

只有下面三种位置可以断开：

1. 空格之后（这个空格被丢掉，不进任何一行，也不计入行宽）；
2. 两个 CJK 单元之间；
3. CJK 单元与英文/数字单元之间（两个方向都算）。

单词、数字、连字符词的内部永远不是断点。行首不保留空格。

## 代价函数

行宽上限 `W` 由调用方给出（样例的行宽见下一节，单位与宽度规则一致）。对每一种断法，总代价是各行代价之和：

- 非最后一行：`代价 = 行尾空隙² + 10`，其中 `行尾空隙 = W − 该行宽度`；
- 最后一行：代价为 0，不罚空隙也不罚断行；
- 断点之间的空隙为负数（行宽超过 `W`）的断法一律不合法；
- 唯一的例外是「单个单元本身就比 `W` 宽」：这时才允许强制拆开该单元，按能放下多少字符就放多少的方式拆，每拆一次记 1000 分，拆出来的行不再受禁则约束（已经排不下，属于降级路径）。

在所有合法断法里取代价最小的一种。代价相同时，取断点更靠前的那种（也就是当前行更长的那种），保证结果唯一。这个最优化用按断点位置递推的动态规划实现即可，转移只在前一行的空隙范围内发生，整体是随文本长度线性增长的。

## 输出格式

每段文本排完后逐行输出，行与行之间用 LF 分隔，文件末尾留一个 LF；行尾不留空格；段与段之间保留一个空行（样例都是单段）。

## 样例与行宽

samples/ 下三段文本，输入是 `text-N.txt`，期望输出是 `text-N.expected.txt`，那就是验收标准：

| 样例 | 行宽 W |
|---|---|
| text-1.txt | 24 |
| text-2.txt | 20 |
| text-3.txt | 32 |

## 实现与使用

代码只用标准库，结构如下：

- `linebreak/widths.py`：宽度表解析与查表（区间按起始码位索引，二分查找）；
- `linebreak/kinsoku.py`：行首/行尾禁则字符表解析；
- `linebreak/tokenizer.py`：文本切单元（单词原子、CJK 单字、前导空格标记）；
- `linebreak/engine.py`：超长单元预拆分与动态规划主流程；
- `tests/test_linebreak.py`：`unittest` 测试，含三个样例的逐字节验收；
- `python -m linebreak`：命令行入口。

命令行：

```
python -m linebreak -w 24 samples/text-1.txt
python -m linebreak -w 20 --widths samples/widths.txt --kinsoku samples/kinsoku.txt < in.txt
```

库调用：

```python
from linebreak.widths import WidthTable
from linebreak.kinsoku import load_kinsoku
from linebreak.engine import layout_text, layout_paragraph

widths = WidthTable.from_file("samples/widths.txt")
no_start, no_end = load_kinsoku("samples/kinsoku.txt")
result = layout_text(text, max_width=24, width_table=widths,
                     no_line_start=no_start, no_line_end=no_end)
```

跑测试：

```
python3 -m unittest discover -s tests
```

### 复杂度与确定性

`dp[i]` 的左端只扫到累计宽度超过 W 为止，行宽固定时每个单元入队常数次，
时间 O(n)，空间 O(n)（200 万单元、W=80 约 11 秒；几十万字的书稿在 1 秒量级）。
算法不含随机、不依赖字典/集合的遍历顺序：宽度区间按起始码位排序后二分，
同代价的并列只按断点位置（左端更小者胜）决策，同一份输入任意跑两遍字节一致。

### 边界约定

- 分隔符只认 ASCII 空格；连续空格按一个空格处理；行首空格一律丢弃。
- 半角片假名宽度表给 1，但属于日文，按 CJK 单元处理（两侧可断）。
- 段内换行折叠为空格，空行分段（Markdown 惯例）；段间输出一个空行。
- 行宽小到连单个全角字符都放不下（W=1）时，该字符独占一行并允许溢出，
  属于 README 中说明的降级路径，不额外罚分；禁则在极端窄行下无合法断法时，
  兜底放宽禁则重排一次，保证任何输入都能排完。
